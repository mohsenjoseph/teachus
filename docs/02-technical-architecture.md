# معماری فنی

## تصمیم‌های پایه
- PHP 8.3
- Yii2 Advanced
- MySQL با موتور InnoDB
- معماری Modular Monolith
- رابط واکنش‌گرا و قابل استفاده روی موبایل
- اجرای کارهای زمان‌بر از طریق صف MySQL و Cron
- ذخیره‌سازی فایل در مسیر خصوصی خارج از webroot، در صورت پشتیبانی هاست

## چرا Yii2 Advanced؟
تفکیک frontend، backend و console برای محصولی که هم محیط والد/کودک، هم پنل مدیریت و هم پردازش زمان‌بندی‌شده دارد مفید است. در نسخه اول از Microservices و API مستقل اجتناب می‌کنیم تا پیچیدگی استقرار روی هاست اشتراکی افزایش نیابد.

## اجزای برنامه
- frontend: صفحات عمومی، ورود، ثبت‌نام، پنل والد و محیط کودک.
- backend: پنل مدیریت، مدیریت محتوا، بررسی و تأیید.
- console: اجرای صف وظایف، تولید محتوا، اعتبارسنجی و انتشار زمان‌بندی‌شده.
- common: مدل‌ها، سرویس‌ها، اعتبارسنجی‌ها و منطق مشترک.

## موتور تولید محتوا
اجزای منطقی:
1. Planner: تعیین موضوع، گروه سنی و برنامه تولید.
2. Text Generator: تولید درس متنی.
3. Quiz Generator: تولید پرسش‌ها و گزینه‌ها.
4. Mission Generator: طراحی مأموریت عملی.
5. Image Generator: تولید تصویر آموزشی.
6. TTS Adapter: تبدیل متن تأییدشده یا آماده بررسی به گفتار فارسی.
7. Validator: کنترل ساختار، تناسب سنی، کامل بودن و موارد ممنوع.
8. Approval Manager: مدیریت تأیید مدیر.
9. Publisher: انتشار بسته تأییدشده.
10. Scheduler: زمان‌بندی تولید و انتشار.

## چرخه وضعیت محتوا
`queued → generating → generated → validating → pending_approval → approved → scheduled → published`

وضعیت‌های جایگزین:
- `failed`: خطای پردازش
- `revision_requested`: نیازمند اصلاح
- `rejected`: ردشده توسط مدیر

انتشار فقط از وضعیت `approved` مجاز است. تأیید باید برای بسته و پس از بررسی کامل اجزای اجباری انجام شود.

## صف وظایف و Cron
- زمان‌بندی تولید روزانه، دو بسته را به صف اضافه می‌کند.
- Cron در فواصل کوتاه، تعداد محدودی کار را اجرا می‌کند.
- هر job باید قفل، زمان انقضا، تعداد تلاش مجدد محدود و گزارش خطا داشته باشد.
- پردازش نباید به اجرای دائمی یا daemon وابسته باشد.
- مسیر واقعی PHP CLI و محدودیت‌های زمان/حافظه باید روی هاست تأیید و آزمایش شوند.

نمونه الگوی Cron (مسیرها باید با هاست واقعی تطبیق داده شوند):
```bash
/usr/local/bin/php /home/ACCOUNT/public_html/yii queue/run
```

این فقط نمونه است؛ نام کنترلر و مسیر نهایی پس از پیاده‌سازی مشخص می‌شود.

## مدیریت فایل
- فایل‌های در انتظار تأیید عمومی نباشند.
- فایل‌ها در دیسک ذخیره شوند و دیتابیس فقط مسیر، نوع، اندازه، وضعیت و metadata را نگه دارد.
- تصاویر با اندازه مناسب و فشرده‌سازی ذخیره شوند.
- صوت با bitrate و قالب بهینه تولید شود.
- فایل‌های موقت و خروجی‌های ناموفق طبق سیاست پاک‌سازی شوند.

## استقرار بدون SSH
با توجه به هاست اشتراکی فاقد Terminal:
1. توسعه و اجرای Composer در محیط محلی Laragon.
2. اجرای Migrationها در محیط توسعه.
3. آماده‌سازی بسته انتشار و حذف فایل‌های توسعه/محرمانه.
4. انتقال فایل‌ها با File Manager یا FTP امن.
5. ایجاد دیتابیس و واردکردن schema/داده‌های لازم با phpMyAdmin.
6. تنظیم فایل‌های محلی و مسیر storage.
7. ثبت Cron از طریق cPanel و آزمایش اجرای CLI.
